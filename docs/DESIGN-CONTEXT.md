# PedalQuest 디자인 컨텍스트

디자인 담당(클로디)에게 넘기는 요약본. **코드 전체 대신 이것만 읽으면 된다.**
`templates/game.html`은 2,300줄이라 통째로 넘기면 맥락이 금방 찬다.

> 갱신: 이 문서에 적힌 `#id`와 `--토큰`이 실제 소스에 있는지 `tests/test_design_context.py`가 검사한다.
> 이름이 바뀌면 테스트가 깨지므로 문서가 조용히 낡지 않는다.

---

## 0. 협업 방식 (중요)

클로디는 claude.ai **채팅**이라 파일 시스템도 git도 없다. 저장소를 클론하거나
커밋할 수 없고, "파일에 반영했다"고 해도 실제 저장소에는 아무것도 들어오지 않는다.
(2026-09-21에 실제로 그런 일이 있었다.)

**그래서 이렇게 주고받는다:**
- 클로디 → Claude Code: **코드가 아니라 사양**. "무엇을, 어떤 값으로, 어디에."
  색은 hex나 rgb, 크기는 px, 위치는 기준 요소(`#stagebar` 아래 등)로.
- Claude Code → 클로디: 이 문서 + 필요하면 스크린샷.

코드를 통째로 주면 기존 기능이 빠진 버전으로 덮어쓸 위험이 있다. 실제로 과거에
"전체 재작성" 사양이 왔다가 기능이 사라질 뻔했다.

## 1. 게임 한 줄 요약

실내 홈싸이클에 BLE 케이던스 센서를 달고, 페달을 밟으면 화면 속 자전거가 달린다.
PC가 서버, **태블릿 브라우저가 화면**(Lenovo TB-X606F, 1920x1200, PowerVR GE8320 — 저사양).

**바꿀 수 없는 제약:**
- **달리는 중 입력은 페달뿐.** 버튼 연타·조준이 필요한 UI는 안 된다. 메뉴만 터치.
- **땀 흘리며 누른다** → 버튼은 크게, 글자는 굵게.
- **오프라인.** CDN·웹폰트·이미지 파일 없음. 전부 코드로 그린다(Canvas + CSS).
- **가로 화면** 기준. 세로면 "가로로 돌려주세요".
- 사람 몸통·다리를 코드로 그리는 연출은 피한다 — 부자연스러웠다. 이펙트·색·실루엣으로.
  (손은 예외: 1인칭에서 핸들바만 떠 있으면 내 몸이 없는 것처럼 보여서 넣었다.)
- **터치 기기에서 `backdrop-filter`(유리 블러)를 쓰지 않는다.** 아래 6번 참고 — 이것 하나로 27fps를 잃었다.

## 2. 파일

| 파일 | 내용 |
|------|------|
| `templates/game.html` | 화면 전체 (CSS + DOM + 2D Canvas 렌더러 + WebSocket + 사운드) |
| `static/render3d.js` | **3D 렌더러 (기본, Three.js)**. 2D와 같은 트랙 데이터를 읽는다 |
| `static/cockpit.js` | 1인칭 콕핏 (2D 오버레이). 팔·핸들바는 PNG, 속도계는 코드 |
| `static/rider3p.js` | 3인칭 뒷모습 라이더. 스프라이트 시트를 속도에 비례해 재생 |
| `pedalquest/*.py` | 서버 (게임 로직·센서·기록). 화면이 받는 데이터의 출처 |
| `art/chr/anime/`, `art/chr/photo/` | 캐릭터 원화 두 벌 (1792x1008). 브라우저에 내려보내지 않는다 |
| `static/chr/*.jpg` | 원화에서 잘라 만든 화면용 이미지. `tools/chr_art.py`가 만든다 |

그래픽 모드는 `G`키 또는 메뉴 칩으로 3D ↔ 2D 전환 (**기본 3D**, `localStorage["pq.gfx"]`).
시점은 `V`키로 1인칭 ↔ 후방 (기본 1인칭, `localStorage["pq.cam"]`).

**2D는 없어지지 않는다.** 3D가 라이벌·고스트·코인·아이템·결승 아치를 2D 그림 함수로
화면에 겹쳐 그리고, WebGL을 못 켜거나 잃었을 때 넘어갈 곳이다.
→ **길가 풍경을 바꾸면 양쪽 다 고쳐야 한다.** 둘은 같은 해시 구간을 써서 같은 자리에 같은 것을 세운다.

## 4. 화면 구조

메인 → 스테이지 선택 → 플레이 → 결과. 화면은 `.screen` 섹션이고 한 번에 하나만 보인다.

| id | 화면 |
|----|------|
| `#v-stages` | 스테이지 선택 (별·최고기록·고스트 토글) |
| `#v-arcade` | 아케이드 코스 선택 |
| `#v-records` | 기록 목록 |
| `#v-achievements` | 업적 (탭 6개) |
| `#v-result` | 결과 |

**캐릭터 아트.** 메뉴의 모드 버튼 4개(`style="--art:url(...)"` → `.mode::before` 사진 +
`.mode::after` 어둠)와 결과 화면 머리띠(`.dialog .hero`). 사진이 카드를 덮으므로 `.mode`의
`backdrop-filter`는 뺐다. 그림은 **카드 비율(약 1.85:1)에 맞춰** 잘라둔다 — 세로로 긴 그림은
`cover`가 위아래를 잘라 머리가 날아간다. 원화가 셀 셰이딩(anime)·실사풍(photo) 두 벌이고
`tools/chr_art.py [--style photo]` 한 줄로 갈린다 (기본 anime — 월드가 셀 셰이딩 저폴리).

**플레이 중 3인칭 라이더**: 스프라이트 시트(`static/cyclist-spritesheet.png` + `…-meta.json`)를
`static/rider3p.js`가 화면 중앙 하단에 겹쳐 그린다(2D·3D 공용). 재생은 **속도에 비례** — 시트가
크랭크 한 바퀴가 아니라 영상을 잘라온 것이라 페달 각도에 물릴 수 없다. 시트가 없으면 기존
`drawRider`로 넘어간다. 메뉴 배경에는 안 쓴다 (어두운 막에 덮여 덩어리로만 보인다).
1인칭 콕핏에는 아직 캐릭터 그림이 없다 — 배경이 그려진 원화는 인물만 오려낼 수 없다.

### 플레이 중 HUD (`#hud`, 화면 전체에 고정)

| 위치 | id | 내용 |
|------|----|------|
| 좌상단 | `#stageinfo` | 거리·시간·칼로리·코인 |
| 상단 중앙 | `#stagebar` | 진행 바 + 고저 미니맵 (`#minimap`). **화면 y 16~98 차지** |
| 상단 중앙 아래 | `#alerts` | 알림 열, **top 108**. 안에 `#toasts`(위) → `#raceBanner`(아래) |
| 우상단 | `#topRight` | `#fpsChip` · `#btnCam` · `#sensorDot` |
| 좌하단 | `#gSpeed` | 속도 (큰 숫자) |
| 우하단 | `#gRpm` | RPM 게이지 (`#rpmRing`, 구간 색) |

| 아케이드 우상단 | `#itemSlot` `#itemBox` | 보유 아이템 + 스퍼트 게이지 `#spurtBar` |

**새 요소를 상단 중앙에 둘 때는 `#stagebar`(y 16~98)와 `#alerts`(top 108)를 피할 것.**
배너를 top:64에 뒀다가 진행 바와 겹친 적이 있다.

## 5. 알림: 토스트 vs 레이스 배너

둘 다 `#alerts` 한 열에 쌓여서 절대 겹치지 않는다.

- **`#toasts` (위)** — 위험·내 일: 개 추격, 미끄러짐, 번개, 라스트 스퍼트, 업적. 3.5초.
- **`#raceBanner` (아래)** — 라이벌 소식: 어택·지침·추월·완주. **최대 2개, 2.8초.**
  색: 어택 `#ffb060` · 지침 `#8eb8d8` · 추월 `#7ee08a` · 경고 `#ff7b6b` · 완주 `--gold`

**이벤트 종류** (서버가 보내는 `kind`):

| 배너로 | 토스트로 |
|--------|----------|
| `rival_attack` `rival_tired` `rival_pass` `rival_passed` `rival_finish` `rival_slip` `bump` | `dog_start` `dog_caught` `dog_escape` `slip` `blocked` `lightning` `last_spurt` `rival_banana` `item_get` `item_use` `boost_pad` `achievement` |

접전이면 라이벌 알림이 11분에 40회 넘게 나온다 → 서버에서 이미 줄여서 보낸다
(어택은 80m 안쪽만, 추월은 라이벌당 12초 쿨다운).

**이름 뒤 조사는 `nm(name, "가")` 헬퍼가 처리한다** (받침 있으면 "이"를 붙임: 민준이가 / 지호가).
문구를 새로 제안할 때 조사는 신경 쓰지 않아도 된다 — "{이름}가 ..." 식으로 써주면 맞춰 넣는다.

## 6. 라이더 상태

서버가 라이벌마다 내려주는 플래그. **세 가지가 동시에 겹칠 수 있다.**

| 필드 | 값 | 지금 표현 |
|------|-----|-----------|
| `effect` | `"turbo"` / `"slip"` / `null` | 터보=불꽃, 미끄러짐=기울기+💫 |
| `attacking` | `true`/`false` | 주황 오라 + 스피드 라인 4줄 + 이름표 `⚡`(`#ffb060`) |
| `tired` | `true`/`false` | 65% 페이드 + 미세 흔들림 + 이름표 `💨`(`#8eb8d8`) |

라이벌 5명은 **성격(`persona_id`)마다 실루엣이 다르다** — 저지 색만 다르면 구별이 안 된다.
체형(`bodyScale`) · 좌우 흔들림(`swayMul`) · 앞으로 웅크린 정도(`leanFwd`) · 헬멧(에어로/라운드/납작).
climber=가늘고 많이 흔듦, sprinter=넓고 안정적, steady=표준, starter=가장 웅크림, attacker=크고 거칢.

내 자전거는 1인칭이면 콕핏(핸들바·후드·속도계·**후드를 잡은 장갑**), 후방이면 뒤에서 본 모습.
다리 회전은 **실제 내 RPM에 맞춰 돈다** — 박자가 어긋나면 몰입이 깨진다.
1인칭에 팔뚝은 넣지 않는다: 카메라 쪽으로 오는 원기둥이 원근으로 굵어져 기둥처럼 보이고 드롭을 가린다.

## 6.5 성능 예산 (디자인 결정에 직접 영향)

태블릿 실측 (Lenovo TB-X606F):

| 상태 | fps |
|------|-----|
| 처음 | 2D 4~7 · 3D 4~7 |
| `backdrop-filter` 제거 후 | 2D 27 · **3D 50** |
| 길가 소품 8종 → 20종 | **3D 50** (변화 없음) |

**여기서 배울 것:** 프레임을 먹은 건 풍경이 아니라 **HUD 패널의 유리 블러**였다.
매 프레임 바뀌는 캔버스를 패널마다 다시 블러하느라, 정작 보는 대상인 세상에 쓸 예산이 없었다.
소품을 12종 더 넣어도 fps가 그대로라는 게 그 증거다.

**싼 것 (마음껏 해도 됨)**
- 길가 오브젝트 **종류**를 늘리는 것 — 인스턴싱이라 종류당 그리기 1번. 8→20종이 공짜였다.
- 모델 자체를 더 정교하게 (삼각형은 싸다, 그리기 횟수가 비싸다)
- 색·팔레트·안개·조명 각도, 하늘, 테마 분위기
- 정점 색으로 개체마다 변화 주기 (같은 모델을 다른 색으로)

**보통 (한 번 재보고)**
- 오브젝트 **밀도**를 높이는 것 (같은 종류를 더 많이)
- 도로 폭·커브·언덕을 더 극적으로

**비싼 것 (하려면 먼저 상의)**
- 그림자 맵, 후처리(블룸·DOF), 반투명이 겹치는 것(비·안개 파티클)
- 오브젝트마다 그리기가 따로 생기는 것 (인스턴싱을 못 쓰는 구조)
- `backdrop-filter`, 큰 `box-shadow`가 매 프레임 갱신되는 영역 위에 오는 것
- 매 프레임 캔버스 텍스처를 GPU로 올리는 것 (속도계는 0.2초에 한 번만 갱신한다)

**30fps면 충분히 탈 만하다.** 지금 3D는 50이라 여유가 있고, 부족해지면
자동 품질 조절이 그리는 거리와 해상도를 먼저 줄인다 → **욕심을 내도 게임이 멈추지는 않는다.**

## 7. 테마 팔레트

2D는 `THEMES`(game.html), 3D는 `T3`(render3d.js). 키는 같다: `city` `suburb` `mountain` `beach` (+3D `night`=아케이드).

2D 한 테마 = `skyTop` / `skyMid` / `skyBot` / `ground[2]` / `verge[2]` / `road[2]` / `edge` / `lane` (전부 `[r,g,b]`).
**`skyBot`은 지평선 색이자 안개 색으로 같이 쓰인다.**

현재 방향: 도시=한낮 · 교외=맑음 · **산악=노을**(skyBot `218,185,168`) · **해변=아침**(skyBot `210,235,248`) · 아케이드=야간 신스웨이브.

3D는 그리는 거리가 기기 성능에 따라 **240~510m 사이에서 변하고 안개 끝도 같이 당겨진다.**
"먼 배경이 항상 보인다"를 전제한 연출은 깨질 수 있다. 2D도 같은 방식으로 420~210m에서 변한다.

길가 소품(테마별):
도시=건물·가로등·나무·네온간판·버스정류장·신호등 / 교외=나무·집·울타리·우체통·꽃밭 /
산악=전나무·바위·가드레일·경고표지판·폭포 / 해변=야자수·파라솔·서핑보드·갈매기(2D만).
노면에 맨홀과 지워진 차선. 전부 도로 바깥(갓길)에만 세운다.

## 8. 사양을 줄 때

이렇게 주면 바로 붙는다:

```
#raceBanner 를 #stagebar 아래(top 108)에 두고,
높이 36px / 글자 16px 800 / 좌측에 4px 색 바.
어택 #ffb060, 지침 #8eb8d8. 최대 2개, 2.8초 후 페이드아웃.
```

이렇게 주면 되묻게 된다:

```
배너를 예쁘게 상단에 배치 (코드는 이미 반영함)
```

새 데이터가 필요하면(예: "라이벌 심박수를 보여주고 싶다") 먼저 말해달라 —
서버에서 안 내려주는 값은 화면에 못 그린다.
